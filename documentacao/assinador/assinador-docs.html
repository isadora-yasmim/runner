03

Principais Funções

⚡

Main

br.go.ses.assinador.Main

Entry point da aplicação. Registra os subcomandos via anotação @Command e delega a execução para o picocli.

  • main(String[] args)
  • call() → Integer
🖊️

SignCommand

br.go.ses.assinador.commands.SignCommand

Subcomando sign. Recebe documento e PIN via flags CLI. Valida os parâmetros e gera uma assinatura simulada com hash fixo e algoritmo SHA256withRSA.

  • call() → Integer
-d / --document -t / --token-pin
🔍

VerifyCommand

br.go.ses.assinador.commands.VerifyCommand

Subcomando verify. Recebe documento e hash da assinatura. Valida os parâmetros e compara o hash com o valor mock esperado.

  • call() → Integer
-d / --document -s / --signature
🛡️

ParameterValidator

br.go.ses.assinador.util.ParameterValidator

Classe utilitária estática. Centraliza todas as regras de validação de parâmetros de entrada. Lança IllegalArgumentException com mensagens descritivas em caso de violação.

  • validateSign(document, tokenPin)
  • validateVerify(document, signature)
📤

JsonUtil

br.go.ses.assinador.util.JsonUtil

Serializa respostas usando Jackson com pretty-print. Sucesso vai para stdout; erros vão para stderr. Garante saída padronizada em todos os cenários.

  • printSuccess(message, data)
  • printError(message)
📦

Modelos

br.go.ses.assinador.model.*

POJOs de dados. ResponseOutput é o envelope padrão de toda resposta. SignatureData carrega o hash e o algoritmo da assinatura gerada.

  • ResponseOutput(success, message, data)
  • SignatureData(signatureHash, algorithm)

→ SAÍDA DE SUCESSO (stdout)

$ assinador sign -d doc.pdf -t 1234
{
  "success" : true,
  "message" : "Assinatura criada com sucesso",
  "data" : {
    "signatureHash" : "mock_hash_abc123...",
    "algorithm" : "SHA256withRSA"
  }
}

→ SAÍDA DE ERRO (stderr)

$ assinador sign -d doc.pdf -t 12
{
  "success" : false,
  "message" : "O PIN do token deve conter
               pelo menos 4 caracteres.",
  "data" : null
}

EXEMPLO — ParameterValidatorTest.java

ParameterValidatorTest.java
@Test
void validateSign_pinMenorQue4Chars_deveLancarExcecao() {
  IllegalArgumentException ex = assertThrows(
    IllegalArgumentException.class,
    () -> ParameterValidator.validateSign("doc.pdf", "123")
  );
  assertEquals(
    "O PIN do token deve conter pelo menos 4 caracteres.",
    ex.getMessage()
  );
}

@Test
void sign_parametrosValidos_deveProduzirJsonComHash() throws Exception {
  String output = tapSystemOut(() ->
    new CommandLine(new SignCommand())
      .execute("-d", "doc.pdf", "-t", "1234")
  );
  assertTrue(output.contains("mock_hash_abc123"));
  assertTrue(output.contains("SHA256withRSA"));
}
05

Dependências

🖥️
picocli
4.7.x
Framework para parsing de argumentos CLI. Suporta subcomandos, flags, geração automática de help e integração com GraalVM.
📦
jackson-databind
2.17.x
Serialização e desserialização JSON. Usado pelo JsonUtil para produzir saídas padronizadas em pretty-print.
🧪
junit-jupiter
5.10.2
JUnit 5 — framework de testes unitários. Scope: test. Provê @Test, assertThrows, assertEquals, assertDoesNotThrow.
🎭
mockito-core
5.11.0
Mocking de dependências em testes. Scope: test. Permite isolar unidades sem instanciar dependências reais.
🔧
system-lambda
1.2.1
Utilitários para testes que dependem de System.out/err e System.exit. Usado para capturar saídas no JsonUtilTest. Scope: test.
📊
jacoco-maven-plugin
0.8.11
Geração de relatórios de cobertura de código. Relatório HTML disponível em target/site/jacoco/index.html após mvn verify.
Comandos úteis
# Compilar e executar todos os testes
$ mvn test

# Gerar relatório de cobertura JaCoCo
$ mvn verify

# Assinar um documento (simulação)
$ java -jar assinador.jar sign -d meu_doc.pdf -t 1234

# Verificar uma assinatura
$ java -jar assinador.jar verify -d meu_doc.pdf -s mock_hash_abc123...

# Compilar para binário nativo (GraalVM)
$ mvn -Pnative package
